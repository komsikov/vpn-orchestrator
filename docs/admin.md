# Веб-панель

Панель показывает состояние оркестратора и активный исходящий туннель. В разделе устройств можно выпустить профиль WireGuard для отдельного устройства, скачать `.conf`, увидеть время последнего рукопожатия и отозвать доступ. Скачайте профиль при создании. Из ключевого материала в серверном конфиге сохраняются открытый ключ устройства и общий ключ соединения.

В разделе исходящих туннелей можно загрузить или вставить конфиг WireGuard или AmneziaWG, заменить его и включать или отключать туннели. Существующий Xray отображается в списке. При неудачном применении исходящего конфига служба пытается восстановить предыдущий набор файлов и перезапустить оркестратор.

## Требования

- Linux с systemd, Python 3.11 или новее, `wg`, `wg-quick`, `ip` и `ping`. Для исходящего AmneziaWG установите `awg-quick` и создайте каталог `/etc/amnezia` при необходимости.
- Действующий `vpn-orchestrator.service` и входящий WireGuard-интерфейс с IPv4-подсетью из `[server].subnet`. В поле `Address` серверного WireGuard-конфига должен быть один IPv4-адрес из этой подсети. Каждый клиент занимает отдельный адрес `/32`.
- Обычный файл входящего WireGuard-конфига с именем интерфейса, например `/etc/wireguard/wg0.conf`. Если `[server].config_path` задан, панель использует этот файл. Для сохранения подписей устройств оставьте `SaveConfig` выключенным.

## Входящий интерфейс

Запускайте входящий WireGuard отдельно от оркестратора. Тогда при применении исходящего конфига клиентские подключения к WireGuard и к панели сохранятся. В примере используются `wg0` и пути из [инструкции по развёртыванию](deployment.md). Подставьте имя своего интерфейса и пути из действующего unit-файла.

Если входящий интерфейс уже поднимает `wg-quick@wg0.service`, проверьте, что оркестратор запускается с `--skip-server`, и переходите к установке панели. Если интерфейс поднимает оркестратор, сначала остановите сервис через SSH. На время переноса входящий VPN прервётся.

```bash
sudo systemctl stop vpn-orchestrator.service
sudo systemctl enable --now wg-quick@wg0.service
sudo systemctl edit vpn-orchestrator.service
```

Сохраните в drop-in такие параметры с именем своего интерфейса и путями из установленного сервиса.

```ini
[Unit]
Requires=wg-quick@wg0.service
After=wg-quick@wg0.service

[Service]
ExecStart=
ExecStart=/usr/local/bin/vpn-orchestrator -c /etc/vpn-orchestrator/config.toml --skip-server
```

```bash
sudo systemctl start vpn-orchestrator.service
sudo systemctl status wg-quick@wg0.service vpn-orchestrator.service
```

`wg-quick@wg0` читает `/etc/wireguard/wg0.conf`. Если используется нестандартный путь, убедитесь, что независимая служба WireGuard читает тот же файл, который указан в `[server].config_path`.

## Установка и вход

Из корня репозитория установите файлы панели, откройте её конфиг и задайте пароль администратора. Повторная установка сохраняет текущий конфиг панели и хеш пароля.

```bash
sudo bash admin/install.sh
sudoedit /etc/vpn-orchestrator-admin/config.toml
sudo /usr/bin/python3 -Es /usr/local/libexec/vpn-orchestrator/admin/set_password.py admin
sudo systemctl daemon-reload
sudo systemctl enable --now vpn-admin-worker.socket vpn-admin.service
```

В поле `endpoint` укажите публичный IPv4-адрес или DNS-имя сервера и UDP-порт входящего WireGuard, например `vpn.example.net:51820`. Это значение попадёт в скачанные профили. Параметры `client_dns` и `client_mtu` задают DNS и MTU новых профилей. `orchestrator_config` должен совпадать с путём, который Rust-служба получает через `-c`.

По умолчанию панель доступна на `127.0.0.1:8787` сервера. Откройте SSH-туннель со своей машины, подставив имя пользователя SSH и адрес сервера.

```bash
ssh -N -L 127.0.0.1:8787:127.0.0.1:8787 user@vpn.example.net
```

Откройте [панель через SSH-туннель](http://127.0.0.1:8787) и войдите с заданным паролем. При изменении `listen_port` замените номер порта в команде и адресе. Для доступа из WireGuard задайте в конфиге панели `vpn_bind_ipv4` и `vpn_client_network` по адресу и частной подсети RFC 1918 входящего интерфейса. Перезапустите панель и откройте `http://<адрес WireGuard>:8787` на подключённом устройстве.

Для смены пароля снова запустите `set_password.py` и выполните `sudo systemctl restart vpn-admin.service`. Перезапуск завершит существующие сеансы панели.

## Доступ к файлам и маршрутизация

HTTP-служба работает от пользователя `vpn-admin`. Чтение и изменение конфигураций, вызовы `wg syncconf` и перезапуск оркестратора выполняет отдельная root-служба через Unix-сокет с режимом `0660`. Оставьте доступ к группе `vpn-admin` служебной учётной записи. Пароль хранится в виде хеша scrypt с солью.

Панель создаёт исходящие конфиги WireGuard в `/etc/wireguard` и AmneziaWG в `/etc/amnezia`. Для исходящих конфигов, добавленных через панель, используются `Table = off` и IPv4-маршрутизация оркестратора. При нестандартном размещении входящего конфига или `orchestrator_config` добавьте их родительские каталоги в `ReadWritePaths` через `sudo systemctl edit vpn-admin-worker@.service`.

После изменения исходящих туннелей существующим интернет-соединениям может потребоваться переподключение. При отказе всех исходящих туннелей оркестратор временно использует прямой IPv4-выход через сервер. [Маршрутизация и failover](configuration.md)
